## 已经完整的玩法

- 五天中每天可选一次主行动。六项行动均由规则实际改变资源，赞助仅一次，接受共同署名可获得一次搭建折扣。事件处理、胜败和回合记录已经闭环。
- 玩家可以看到海报、摊位、围观人数和部长心情变化。地图是与数值绑定的像素舞台。围观精灵的上限是 12，角色站位按条件切换。
- 首局的动力是 ¥500 与五天期限，以及第一天动作立刻带来的画面变化。第二局已有同种子和换种子、宣传优先与联动优先的路线，但这些路线仍围绕同一组阈值。玩家是否想主动复玩尚无人工样本。
- 人物、活动及默认台词是虚构素材，位置与数值由规则驱动。主流程里的按钮、日志和结局都有对应行为。规格书中列为后续的社团类型、成长与图鉴在此版本中没有实现。

## AI 实际掌握的决策

模型只在满足前置条件的事件中选一个，并写台词与原因。事件不同，下一天可做的处理也不同。例如借场地给玩家署名折扣，意见分歧则让玩家在准备时间与凝聚力间取舍。角色、事件选项、费用和胜负由程序决定。赞助后只有一个合法事件，或者无事可发时只有「计划照常」，这类调用没有分支可选。固定种子模式由本地加权规则选事件，不请求模型。

## 按影响排序的发现

| 影响 | 证据与后果 | 最小调整 |
| --- | --- | --- |
| 高 · 重复行动缺少代价 | P0 `actionEffect` 只对一次性场地优惠与海报疲劳分支处理。反复买同一种行动仍有相同基础收益。报名没有容量限制。多拉人几乎只有正收益。 | 引入接待上限和熟悉行动的边际收益变化。行动前展示其可兑现增量。 `rule/name-object-scope-consequence` |
| 高 · 复练失真与中断 | 浏览器实测刷新清空、同局按钮回到实时模式。重新开局会丢到第四天的取舍。 | 按回放校验本地进度，同种子复练明确切到固定种子。 `rule/preserve-user-input` |
| 高 · AI 选完事件便退出经营决策 | 实时结果只有事件 ID、原因、台词。NPC 心情影响部分事件资格，信息主要藏在角色状态和日志。赞助与安静回合仍可能调模型。 | 让部长带一个有成本、有失效条件的提案，进入具体行动结算。没有分支的回合在规则层直接推进。 `rule/name-object-scope-consequence` |
| 中 · 预览与实际不完全一致 | 行动卡展示基础变化，结算才截断到 100。场景围观随报名增多，空间紧张、支援过期和资源溢出难从画面发现。 | 行动卡用同一规则求实际变化，广场显示候补与部长提案。 `rule/success-state-specific` |
| 中 · 等待和选择连接弱 | 实时模式四次等待合计约 10.4 秒。行动先结算，期间主行动被锁定，已有跳过入口。当前标注不解释新局是否能复现。 | 保留本地结算与跳过，将运行方式和本回合出处分开，减少无分支调用。 `rule/loading-state-specific` |
| 中 · 场次相似 | 固定种子能换事件组合，开局预算、目标、场景条件都相同。 | 加一个低预算雨备场，展示其规则差异。 `rule/smallest-intervention` |

## 工程风险

- React 组件同时做 UI、回合推进和网络回调。现有纯规则引擎和请求版本守卫可复用。持久化应记录回放命令并重跑规则，避免把未经校验的浏览器对象当作进行中状态。
- 导演请求与事件规则依赖同一个结构，但当前请求中的局面来自客户端。并发限制和去重只对单 Node 进程有效。若未来向公网开放，需要单独做访问和模型额度治理。
- 现有客户端可以立即计数，后端响应才开放下一天。浏览器断网会降级。四次真实调用用于确认可用性，无法反映并发或尾延迟。
- 广场背景约 402 KB。桌面和手机流程没有观察到阻塞；本轮不凭素材体积推断低端手机的加载性能。规则计算的数据规模仅五天，现有主要等待来自模型请求。

像素舞台、预算反馈、失败分支与跳过入口都在基线中可用，适合继续沿用。交互发现采用 product-design 的流程审查规则；平衡、延迟与请求信任边界属于游戏及工程证据。
