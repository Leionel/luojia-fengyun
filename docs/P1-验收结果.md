## 玩起来有什么变化

| 维度 | P0 | P1 已验证 |
| --- | --- | --- |
| 经营目标 | 达到报名、准备度和凝聚力阈值 | 报名还要有空间接待。五天只宣传的固定种子局积累了 48 人报名，准备度 67、凝聚力 40，但场地只接待 20 人，28 人候补，得到专门的改期结局。 |
| 行动取舍 | 同类行动的基础收益从头到尾一致 | 常规宣传的第二次基础报名收益从 +12 变为 +10。搭建、彩排和联动都能扩容，后两者组成了可获胜的低开销路线。 |
| NPC 与 AI | 从合法事件中选一个，事件再给一对处理选项 | 选择「事件＋部长提案」，例如多花 ¥10 加测动线，换来额外 5 人接待量。保留选择采用或取消的权利。 |
| 画面与反馈 | 卡片中的像素广场，人物和摊位按数值显示 | 全屏广场上直接操作。发言人物、候补队伍、雨天侧门或连廊的位置可见。结算切至灯火市集。行动卡、数字增减、动画和账本共享同一套结算。 |
| 复玩与中断 | 一个起始局面，刷新清空，实时局重练仍走模型 | 樱花常场与低预算雨备场。刷新恢复已结算动作，等待中刷新自动回到规则分支。可选择固定种子重练。 |

## 真实模型验证

武大 MaaS 的 `deepseek-v4-flash` 在浏览器整局返回了四次合法选择。首日选择「社团联动」后约 1.0 秒，小予带来排班冲突并提出「加测两条动线」。原计划彩排花 ¥40，勾选后花 ¥50。玩家在界面关、开提案核对预览，再采用提案。预算由 ¥460 变为 ¥410，接待上限按预览增加 11 人，其中 5 人来自提案。最终 40 人报名、接待上限 57、结余 ¥210，顺利开场。

早期接入测试遇到超时，也出现推理 token 用完输出额度后正文为空。改用该网关实测支持的 `reasoning_effort: "none"`，并让模型返回已校验候选的编号。异常结果由本地规则接回，游戏继续结算。本次真实整局证明了接入与结算链路，服务并发和长时尾延迟未测。

## 自动化与可复现验收

| 检查 | 结果 |
| --- | --- |
| `npm run build` | 生产构建与 TypeScript 校验通过。 |
| `npm test` | 11 项通过。覆盖固定种子、容量、重复动作收益、相同事件的不同提案、失效与越权、存档重放和降级。 |
| `npm run test:e2e` | Edge 下 7 项通过。包含 1366×768 全屏、375px 触屏全屏操作、候补失利、胜利、刷新恢复与异常接管。 |
| 480 局固定种子模拟 | 11 种事件和 6 种结局均可达。樱花常场 143/240、雨备场 129/240 开场。模拟用于验证规则，P0 与 P1 的随机采样序列不同，不作胜率趋势比较。 |

作品的首局理解时间和主动复玩意愿需要现场观察。完整真实模型测试用的是预设虚构校园数据。

## 新场景素材

两张图用内置 imagegen 以同一张 P0 广场为参考图编辑。位置和透视沿用原图，游戏在同一坐标系绘制摊位、人物、海报和入口。

- [雨备场](../public/art/sakura-rain.webp) 的提示词要求保留院落、屋顶、树、空地、像素密度和取景，加入蓝灰色春雨、湿石砖和积水倒影，保持中心和近处留空。
- [灯火市集](../public/art/sakura-festival.webp) 的提示词要求保持同一比例、视角、建筑和树的位置，只在后侧围墙放灯笼与彩旗，让老楼窗户亮起暖灯，保留广场中央的空地给游戏角色与摊位。
