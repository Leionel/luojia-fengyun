# Campus Chaos 3.0 完整学年改造实施计划

日期 2026-11-19。由[产品 GDD](CAMPUS_CHAOS_3_PRODUCT_GDD.md)定义体验，[架构](CAMPUS_CHAOS_3_ARCHITECTURE.md)定义协议，[内容手册](CAMPUS_CHAOS_3_EVENT_BIBLE.md)定义人物与事件数据，[验收](CAMPUS_CHAOS_3_ACCEPTANCE.md)提供测试编号。本轮只交付这五份规划。以下路径均相对 `campus/`，标明「新」的文件在实施时创建。已有文档（P0/P1 和五日 README）继续作为兼容基线。

## 1. 实施顺序和可玩里程碑

选择「五日挑战兼容＋独立学年领域核」的混合方案。先打通能看到其他社团争资源的九月，再把同一个世界跑到六月。批次排序以可玩的接缝为单位，六大系统都在正式交付范围。

| 批次 | 可运行交付及现场演示 | 依赖与回滚 | 人日预估 |
| --- | --- | --- | --- |
| A 可走完的学年骨架 | 学年入口 → 争展位 → 学期目标和章末反馈 → 轮值或初版换届 → 保存、刷新再走；每章已经有一种独特决策和一个场景变化。浏览器仍可读旧五日档。 | 先冻五日基线；年度路由并行开。任一旧档回归，保持旧首页并保留年度测试入口。快照不可恢复时勿切主入口。 | 6–9。首个切片及旧档隔离较可估，首次 IndexedDB 事务较不确定。 |
| B 人物和社团各自行动 | 同种子走合作/拒绝，对照至少两个人物和一个外社的动作、预约或态度确实不同；模型在浏览器中选择合法动作并落账。L1、L3 跨月能解释和回看。 | 依赖 A 的命令、占用与日历。异常可切固定导演、保留所有规则处理并将真实接入标为待通过。 | 8–13。规则与关系较可估，多角色响应与延迟不确定。 |
| C 自由谈判、角色成长与交付 | 音乐节从自由文本拆方案、修改、模型反价、部分签约，到查看实际履约；期末跨项目撞人能替班。培养可解锁双入口、三方谈判。L2 跨月可见。 | 依赖 B 的授权和外社布局，共享一个结算入口。各动作可用结构化入口调试；版本错或网关中断保留草案和签署事实。 | 10–16。多人反价、实际输入表达和冲突样本是主要变数。 |
| D 全年内容、年鉴、继承与发行 | 两学期 24 窗口全部可玩，四路线各可达、可混合。全屏多场景，成熟期角色带着合同去换届，新一年可以开始。真实 AI 黄金路径、五日回归和试玩。 | 等六系统验收；切换首页独立开关或路由变更能回滚到入口；年度档可通过明确链接回读，不删。 | 10–17。事件和 QA 容量可估，肖像动效和试玩返工不确定。 |

合计预估 34–55 个有效人日，按现有代码与上述分场景体量估计。分支覆盖、模型响应和陌生人首轮体验在每批结束后重新测量，再更新工作量。多条泳道可缩短日历时间，整合与真实试玩仍有顺序。

## 3. 首批直接开工顺序

1. 从 `campus` 建立五日基线。运行 `npm test`、`npm run build`、`npm run test:e2e`。Windows 现有 Edge 可用 `$env:CAMPUS_TEST_BROWSER_CHANNEL='msedge'`。在首次修改前留存旧 API、存档和场景的对照夹具。
2. 开 A1。新增年度路由及世界类型、两个可争用资源的主体、一个排他展位和一个参与人。用 `fair-01` 从真实按钮提交有版本的联摆或抢位，输出命令收据和地图投影。首个切片以当场看见人物和场次变化为完成条件。
3. 完成 A2 事务，刷新核对 A1 的展位、账本与待处理选择。A3 同时实现六章最小节点和可移交的六月归档，让开学竞争结果留到六月。在 A1 契约完成后即可分别推进 B1、B2、B4、C1 草案和 D3 场景表现。
4. B 完成后优先整合 C2 与 C3 的签署到交付。用音乐节故事技术验证一次短话解析、实体消歧、可编辑、真反价、锁资源、失败恢复和证据。合并后跟进 C4、C5 和 D2，最后推进 D4/D5。
5. 下一轮记录实现偏差到 `docs/CAMPUS_CHAOS_3_EXECUTION_NOTES.md` 的「偏差」小节，注明原方案、实测来源、改动为何仍满足目标。按决策对照校验，普通可逆细节直接调整。

工作区当前根目录没有可用 Git 元数据的证据。实施使用真正的仓库分支或隔离工作目录时先确认版本控制位置。无版本控制时保存旧源文件和测试夹具，按表把独立目录的切片合入。高冲突处只有 `model/commands/events`、`turn.ts`、`storage/idb.ts`、`YearShell.tsx` 和首页。指定同一集成人拥有命令/事件版本和 ID，调度/持久化分别只从共享协议接入，内容和美术不要改这些文件。实现前明确工作树中既有修改。此计划是本地执行任务，未发布或分派工单。
